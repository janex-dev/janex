# Java Writer

`janex-writer` provides `org.glavo.janex.writer.JanexWriter` and `PackOptions` on Java 17 or newer.
It uses `janex-reader` for checksums, archive parsing, and application validation. The Gradle plugin
calls it directly; packaging requires no native CLI or network access beyond Gradle dependency resolution.

```java
PackOptions options = new PackOptions(Path.of("app.jar"), Path.of("app.janex"));
options.mainClass = "example.Main";
options.classPath.add(Path.of("library.jar"));
options.arguments.add("--demo");
options.withLauncher = true;
JanexWriter.write(options);
```

The primary input may also be a directory. Imports preserve original resource bytes, JAR names,
empty directories, relative symbolic links, and available permission bits. Timestamps are omitted.
Multi-Release JARs become ordered Java-version layers. Inputs are bounded and must remain unchanged
during writing. Repeated file contents share blobs after byte-for-byte comparison.

`new PackOptions(List<Path> directories, Path output)` merges directories into one primary root.
The list is copied, missing directories fail, duplicate directories merge, and duplicate files or
links fail. `sourceName` sets this root's JAR identity without creating an archive. An empty list
permits a manifest-only root. `normalizeSourcePermissions` uses 0644 for primary files and 0755 for
directories; dependencies and symbolic links retain their original handling.

`manifestAttributes` overrides main attributes before Multi-Release layers and entry-point inference
are processed. Existing named sections are preserved; an empty map leaves the manifest unchanged.
Names must be valid and unique ignoring case, and values must not contain CR, LF, or NUL.

`externalClassPath` and `externalModulePath` accept `PackOptions.ExternalDependency` declarations;
these are recorded without downloading or resolving transitive dependencies. The application reader
validates URI and module-requirement syntax. A `mainModule` places the primary input on the module path.

The writer emits format 0.1 with XXH3-64 file checksums and SHA-256 coverage for sections, decoded
table pages, and nonempty wrappers. Metadata uses a SHA-256 checksum or the configured publisher
signature. Blobs and table pages use dictionary-free Zstandard
when compressed bytes plus encoding overhead are smaller. Set `options.compression = false` to
disable compression. The encoder uses zstd-jni at build time, with `compressionLevel` defaulting to 3;
the generated application's decoder remains portable Java.
CLASSFILE transforms share constant-pool strings and class-name components with resource names.
The writer compares complete pools with and without transforms, retaining the smaller representation.
Set `options.transformClassfiles = false` to disable this step. Malformed class resources and Modified
UTF-8 strings that cannot round-trip through the pool retain their original bytes.

`options.signer` accepts `CmsSigner`, `OpenPgpSigner`, or a caller implementation of `PackageSigner`.
The built-in signers use Bouncy Castle without registering a global security provider. CMS supports
RSA/SHA-256, RSA/SHA-512, P-256/SHA-256, and P-384/SHA-384; OpenPGP additionally supports Ed25519
with SHA-256 or SHA-512. Loaders accept encrypted keys and keep passwords out of signer state.
OpenPGP selects a certified signing subkey or primary key and rechecks its authorization at signing time.
Callers authorize certificates and provide current revocation information; no network lookups occur.

```java
options.withLauncher = false;
options.signer = CmsSigner.load(Path.of("publisher.pem"), Path.of("publisher-key.pem"), password, null);
```

Signing covers the exact metadata and verification tag after resource selection. Every section and
nonempty wrapper remains covered by SHA-256. A fixed `options.signingClock` fixes the signing time;
CMS RSA and version-4 OpenPGP RSA/Ed25519 signatures are deterministic for identical inputs and times;
ECDSA and version-6 OpenPGP may use randomness.
Signed packages require `withLauncher = false` and an authenticating Janex Host. Native prefixes embed
the public signer certificate. The standalone Java launcher does not supply an authentication policy.

The optional JAR tail is generated by `:janex-bootstrap:jar` and bundled as a writer resource during
the Gradle build. Generated JARs stay out of source control. `nativeLauncher` accepts an unsigned PE
or ELF prefix; `nativeLaunchMode` selects `bootstrap` or `direct` independently of `withLauncher`.

Writing requires a new destination and uses a synced temporary sibling before publication.
The Gradle task additionally preserves the previous output on writer failure. Tests cover deterministic
output, resource layers, bounds, corruption detection, Java-only packaging, and Rust interoperability.
